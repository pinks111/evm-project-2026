# Сетевой протокол игры

Описание соответствует текущему серверу. Для сборки и запуска см. [README](../README.md#сборка-и-тесты-на-windows).

## Подключение и формат

- IPv4 TCP, порт `2024`. На том же компьютере подключайся к `127.0.0.1`, по локальной сети — к IPv4-адресу хоста.
- Каждая команда и каждый ответ — одна строка UTF-8, завершённая LF (`\n`). Клиент отправляет именно LF: сервер не убирает `\r` из CRLF. В примерах разделитель опущен.
- TCP может разделить строку на несколько чтений или доставить несколько строк вместе. Клиент накапливает байты до LF, разбирает все полные строки и сохраняет остаток до следующего чтения.
- Лимит входящей команды — 1024 байта без LF. Если команда длиннее, сервер закрывает соединение. Всего два места, третье подключение сервер закрывает без текстового ответа.
- Соединение остаётся открытым на время лобби, боя и следующих матчей. `OK ...` и `ERR_...` приходят отправителю команды. Обновления состояния и события матча могут прийти в любой момент, в том числе пока игрок ничего не отправляет.

## Команды клиента

| Команда | Ответ при успехе | Действие |
| --- | --- | --- |
| `JOIN <имя>` | `OK JOIN` | Задаёт имя один раз на подключение. Имя — непустой текст после `JOIN `, может содержать пробелы. |
| `READY` | `OK READY` | Отмечает игрока готовым. Оба вошли и готовы — начинается матч. |
| `MOVE <x> <y>` | `OK MOVE` | Перемещает персонажа на соседнюю свободную клетку. |
| `ATTACK <x> <y>` | `OK ATTACK` | Атакует соперника, стоящего на указанной соседней клетке. |
| `END_TURN` | `OK END_TURN` | Передаёт ход сопернику и восстанавливает его действия. |

Команды чувствительны к регистру. В `MOVE` и `ATTACK` каждая координата занимает одну цифру, разделитель — один пробел. Например, `MOVE 1 0`. На текущем поле допустимы координаты от `0` до `4`. Начало координат в левом верхнем углу, `x` растёт вправо, `y` — вниз. Соседними считаются клетки по вертикали или горизонтали. За свой ход игрок может один раз переместиться и один раз атаковать в любом порядке. Ход передаётся отдельной командой.

ID игрока определяется по его подключению. Сервер сообщает его в поле `you`. В командах боя ID не передаётся.

| Ошибка | Когда приходит |
| --- | --- |
| `ERR_ALREADY_JOINED` | Повторный `JOIN <имя>` на том же подключении. |
| `ERR_JOIN_FIRST` | `READY` до входа через `JOIN`. |
| `ERR_NOT_IN_MATCH` | Распознанная команда боя вне матча. |
| `ERR_INVALID_MOVE` | Некорректные координаты, чужой ход или запрещённое перемещение. |
| `ERR_INVALID_ATTACK` | Некорректные координаты, чужой ход или запрещённая атака. |
| `ERR_NOT_YOUR_TURN` | Попытка завершить чужой ход в матче. |
| `ERR_UNKNOWN_COMMAND` | Сервер не распознал строку, например `MOVE` без пробела и аргументов. |

## Состояние лобби

`LOBBY_STATE ` — префикс, после которого идёт JSON-объект. Сервер отправляет полный список каждому вошедшему игроку. Клиент может целиком заменить им предыдущий список.

```text
LOBBY_STATE {"you":1,"players":[{"id":1,"name":"Artem","ready":true},{"id":2,"name":"Nikita","ready":false}]}
```

`you` — ID получателя (1 или 2), `players` — массив игроков, которые уже отправили `JOIN`. У каждого игрока есть числовой `id`, строковый `name` и логический `ready`. Если одно из мест свободно, его элемента в списке нет. Один и тот же список может прийти с разным значением `you` у двух клиентов.

## Состояние боя

`GAME_STATE ` содержит полный JSON-снимок поля. Оба клиента получают одинаковый снимок, а свой ID берут из лобби. Порядок полей JSON может различаться, поэтому обращайся к ним по имени.

```text
GAME_STATE {"width":5,"height":5,"blocked":[],"turn":1,"can_move":true,"can_attack":true,"players":[{"id":1,"x":0,"y":0,"hp":10},{"id":2,"x":4,"y":4,"hp":10}]}
```

- `width`, `height` — размеры поля. `blocked` — массив координат препятствий в виде пар `[x,y]`.
- `turn` — ID текущего игрока. `can_move` и `can_attack` — оставшиеся возможности именно этого игрока. Для включения кнопки на клиенте проверяй и соответствующий флаг, и `turn == you`.
- `players` — массив персонажей с числовыми полями `id`, `x`, `y` и `hp`. `id` совпадает с ID игрока из лобби.

## Порядок сообщений

| Событие | Что получает клиент |
| --- | --- |
| Успешный вход или готовность в лобби, пока матч не стартовал | `OK JOIN` или `OK READY` отправителю, затем `LOBBY_STATE` всем вошедшим. |
| Последний `READY` | `OK READY` отправителю, затем `MATCH_START` и начальный `GAME_STATE` обоим. Между стартовым `READY` и `MATCH_START` отдельного `LOBBY_STATE` нет. |
| Принятое действие в бою | `OK <команда>` отправителю, затем новый `GAME_STATE` обоим. Отклонённая команда возвращает только ошибку. |
| Решающая атака | `OK ATTACK` отправителю, затем обоим финальный `GAME_STATE` с нулевым HP проигравшего, `GAME_OVER <id победителя>` и `LOBBY_STATE`. |
| Игрок отключился | В лобби оставшемуся игроку приходит `LOBBY_STATE`. Во время боя сначала приходит `MATCH_ABORTED`, затем `LOBBY_STATE` со сброшенной готовностью. |

После `GAME_OVER` сервер оставляет обоих игроков в лобби на тех же подключениях и сбрасывает их готовность. Для повторного матча достаточно двух новых `READY`.
