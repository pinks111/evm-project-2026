# ToDA 3 — пошаговая сетевая PvP-игра

Учебный проект на C++20 для двух игроков. Каждый управляет персонажем в окне
raylib. TCP-сервер ведёт лобби, проверяет действия и рассылает состояние поля.
Клиент и сервер собираются на Windows, macOS и Linux.

## Сборка

Нужны CMake 3.21+ и C++-компилятор с поддержкой C++20. Заголовок
`nlohmann/json` уже находится в `third_party`. CMake использует Raylib 6.0,
если она установлена, иначе скачивает и собирает её исходники. Homebrew не
обязателен; при первой конфигурации нужен интернет. На Linux могут понадобиться
системные графические библиотеки для Raylib (например, X11 и OpenGL).

Из корня проекта:

```sh
cmake -S . -B build
cmake --build build --config Release
```

Собираются два приложения: `game-server` и графический `game-client`.

## Запуск на одном компьютере

На macOS и Linux открой два терминала:

```sh
./build/game-server
./build/game-client Player1 127.0.0.1
```

Открой ещё один клиент в отдельном терминале:

```sh
./build/game-client Player2 127.0.0.1
```

На Windows с генератором Visual Studio исполняемые файлы находятся в
`build/Release`:

```powershell
.\build\Release\game-server.exe
.\build\Release\game-client.exe Player1 127.0.0.1
.\build\Release\game-client.exe Player2 127.0.0.1
```

Если не указывать ник или IP, клиент предложит ввести ник в окне, а затем
подключится к `127.0.0.1:2024`. Сервер слушает порт `2024`.

## Игра по локальной сети

Запусти сервер на компьютере-хосте. На нём же можно открыть первый клиент,
используя адрес `127.0.0.1`. Узнай LAN IPv4 хоста и запусти второй клиент,
указав этот адрес вместо `127.0.0.1`, например:

```sh
./build/game-client Player2 192.168.1.34
```

На Windows адрес можно найти командой `ipconfig`. Если брандмауэр спросит,
разреши серверу принимать подключения в частной сети.

## Управление

У каждого персонажа 10 HP. Красный начинает в левом верхнем углу и ходит
первым; синий начинает в правом нижнем.

| Управление | Действие |
| --- | --- |
| ЛКМ по соседней свободной клетке | Переместиться на одну клетку по горизонтали или вертикали. |
| ПКМ по клетке соперника | Нанести 1 урон, если соперник стоит на соседней клетке. |
| **T** | Завершить ход, даже если остались действия. |
| **R** в лобби | Подтвердить готовность к матчу или реваншу. |

Когда HP одного игрока падает до нуля, оба клиента показывают результат и
возвращаются в лобби. Если соперник отключится во время матча, матч прервётся.

## Протокол и тесты

Клиент отправляет команды `JOIN`, `READY`, `MOVE`, `ATTACK` и `END_TURN`.
Сервер проверяет очередь и допустимость действий, затем отправляет обновлённые
`LOBBY_STATE` и `GAME_STATE`. Подробности — в [описании протокола](docs/protocol.md).

PowerShell-тесты сервера запускаются на Windows: запусти сервер, затем в другом
окне PowerShell из корня проекта выполни:

```powershell
powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File .\tests\end-turn.ps1
powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File .\tests\attack.ps1
powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File .\tests\game-over.ps1
```
